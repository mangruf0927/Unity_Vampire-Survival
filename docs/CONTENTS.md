# 3D 생존 게임 기준 기획서

- 작성일: 2026-11-04
- 목적: 기능을 하나씩 구현할 때 참고하는 프로젝트의 기준 기획서
- 참고 게임: [Vampire Survivors](https://namu.wiki/w/Vampire%20Survivors)
- 문서 상태: 사용자가 확정한 요구사항과 검토 과정에서 나온 제안·미결정 사항을 구분한다.

## 1. 문서 사용 원칙

- 전체 목표를 기록한 문서이며, 모든 기능을 한 번에 구현하라는 의미가 아니다.
- 앞으로 사용자가 요청하는 기능만 하나씩 구현한다.
- 아래의 **확정 기획**은 구현 기준으로 사용한다.
- **권장안**은 제안이며 사용자 승인 없이 확정 요구사항으로 취급하지 않는다.
- **미결정 사항**은 해당 기능 구현 전에 확인한다. 특히 장신구의 애매한 적용 방식을 임의로 결정하지 않는다.
- 새롭게 합의한 내용은 이 문서에 반영하여 기준을 유지한다.
- 참고 게임과 설명이 다른 경우, 사용자가 명시한 이 프로젝트의 규칙을 우선한다.
- 참고 링크는 초기 검토 당시 직접 열리지 않았으므로, 이 문서는 사용자가 제공한 설명을 기준으로 작성했다.

## 2. 게임 개요 — 확정 기획

| 항목 | 내용 |
| --- | --- |
| 장르 | 3D 뱀파이어 서바이벌 스타일 생존 게임 |
| 최종 목표 | 약 10분 동안 플레이할 수 있는 프로토타입 완성 |
| 승리 조건 | 10분 동안 생존 |
| 패배 조건 | 플레이어 현재 체력이 0 이하 |
| 조작의 중심 | 이동과 레벨업 선택 |
| 공격 | 별도 공격 키 없는 자동 공격 |
| 일반 적 | 박쥐, 좀비, 스켈레톤, 유령, 머드맨의 5종 |
| 보스 | 등장하지 않음 |
| 초기 제외 범위 | 장신구 해금 조건, 무기 진화 시스템 |

### 핵심 진행 흐름

플레이어 이동 → 적 생성 및 추적 → 플레이어 자동 공격 → 적 처치 → 경험치 획득 → 레벨업 → 무기 또는 장신구 획득·강화 → 생존

### 시작 화면 — 현재 구현 범위

- StartScene의 StartCanvas/StartPrompt에 “시작하려면 아무 키나 누르세요”를 표시한다. 현재 환경의 한글 폰트를 사용하는 uGUI Text이며 운영체제 폰트 후보를 사용한다. 폰트를 프로젝트에 복사하지 않는다.
- StartScreenUI가 기본 0.7초 간격으로 문구를 켜고 끈다. Blink Interval은 Inspector에서 수정할 수 있다.
- Input System의 Keyboard.anyKey가 새로 눌리면 GameScene을 로드한다. 마우스·게임패드 입력은 이번 키보드 시작 기능에 포함하지 않는다. 씬 전환 요청은 한 번만 실행한다.
- 시작 화면 진입 시 Time.timeScale을 1로 설정한다. StartScene과 GameScene을 빌드 씬 목록에 등록하고, StartScene을 첫 씬으로 둔다. 기존 SampleScene 등록은 유지한다.
- 게임 오버·나가기 버튼은 아래 규칙으로 구현한다. 게임 클리어는 10분 생존 시 처리한다. 같은 프레임의 사망/10분 도달은 클리어 우선으로 처리하기로 확정했다.

### 게임 진행 상태와 게임 오버·클리어

- 씬에 배치한 GameManager 하나가 Playing/GameOver/Completed/Paused/ChoosingUpgrade 상태를 관리한다. 싱글턴이나 별도 상태 클래스는 사용하지 않는다.
- GameManager는 IObserver로 PlayerHealth를 구독하고, HP 0을 감지하면 사망 요청을 기록한다. LateUpdate에서 TimeSystem의 누적 시간이 600초 이상인지 먼저 검사하고, 클리어가 아니면 사망 요청을 처리한다. 결과는 한 번만 확정하고 Time.timeScale을 0으로 설정한다.
- GameManager가 PlayerHealth, TimeSystem, GameOverUI, GameClearUI, PlayerHPBar를 SerializeField로 직접 참조한다. UI는 GameManager를 참조하거나 게임 상태를 구독하지 않는다.
- 게임 오버 시 GameManager가 HP 바를 숨기고 결과 패널을 표시한 뒤 플레이어를 비활성화·제거한다.
- GameOverUI와 GameClearUI는 각각 게임 오버·클리어 패널의 Show/Hide와 버튼 선택 표시만 담당한다. PlayerHPBar는 체력 알림만 구독하고 SetVisible로 표시와 위치 갱신을 제어한다.
- 나가기 Button의 Inspector On Click()에서 GameManager.ReturnToStartScene()을 연결한다. 코드에서 버튼 리스너는 등록하지 않는다. GameManager는 중복 전환을 막고 Time.timeScale을 1로 복원한 뒤 StartScene을 로드한다. 종료된 GameManager가 제거될 때도 시간을 복원한다.
- GameScene의 EventSystem/InputSystemUIInputModule과 GraphicRaycaster로 게임이 정지한 상태에서도 버튼 입력을 받는다.
- 클리어 시 별도 GameClearUI 패널에 GAME COMPLETED와 나가기 버튼을 표시한다. 플레이어는 유지하고 HP 바는 숨긴다. 게임 오버 시에는 GAME OVER를 표시한다. 각 패널의 나가기 버튼은 Inspector On Click()으로 같은 GameManager.ReturnToStartScene()을 호출해 StartScene에 복귀한다.

## 3. 플레이어 — 확정 기획

- WASD 또는 방향키로 이동한다.
- 기본 최대 체력과 시작 체력은 100이다.
- 현재 체력이 0 이하가 되면 게임이 종료된다.
- 공격 키를 누르지 않아도 보유 무기가 자동으로 공격한다.

### 확정된 이동 규칙

- 월드 기준으로 이동한다. W·↑는 +Z, S·↓는 -Z, D·→는 +X, A·←는 -X이다.
- XZ 평면에서 이동하며 Y 좌표를 유지한다.
- 대각선 이동을 지원하며 상하좌우 이동과 속도가 같다.
- 이동 방향을 바라보고, 멈추면 마지막으로 바라보던 방향을 유지한다.
- 초기 이동 속도는 초당 5이며 인스펙터에서 수정할 수 있다.
- 입력은 PlayerInput의 Send Messages와 `OnMove(InputValue value)`로 받는다. 기존 Input Actions 에셋의 이동 전용 `Movement/Move`를 사용한다.
- CharacterController.Move로 수평 이동한다. 중력은 적용하지 않으며, 현재 평면 스테이지의 계단·경사 오르기 설정은 0이다.
- Player는 Player 레이어(8), 바닥은 Ground 레이어(9)를 사용하며 Physics 충돌 매트릭스에서 두 레이어 사이의 충돌만 제외한다. 바닥 접촉 보정으로 시작 높이가 상승하는 것을 방지한다.
- 평면 스테이지에서 Player 시작 Y는 1, 바닥 표면 Y는 0, 컨트롤러 Height는 2, Center는 0, Skin Width는 0.08로 유지한다. 바닥은 물리적으로 플레이어를 지지하지 않으며, 향후 벽·장애물은 Ground 외의 충돌 가능한 레이어를 사용한다.
- 이동 방향으로 즉시 움직이되 회전은 초당 720도의 기본 속도로 부드럽게 처리한다. 회전 속도는 인스펙터에서 수정할 수 있다.
- 입력을 놓으면 그 순간의 위치와 회전 방향을 유지한다.
- 경사면이나 다른 Collider와의 겹침 해소에 의한 Y 변화까지 강제로 잠그는 구조는 아니다. 높이 지형을 도입할 때 이동 규칙을 재검토한다.

### 확정된 플레이어 체력·접촉 피해 규칙

- PlayerHealth의 기본 Max Health는 100이며 인스펙터에서 조절한다. 시작 체력은 최대 체력과 같다.
- EnemyMovement의 기본 Damage는 float 10이며 적 프리팹에서 조절한다. PlayerHealth의 Damage Interval 기본값은 1초이며 Player 인스펙터에서 조절한다. 접촉 피해용 별도 컴포넌트는 사용하지 않는다.
- 플레이어 공통 피해 간격을 사용한다. 피해를 받은 뒤 PlayerHealth의 Damage Interval 동안 다른 적의 피해도 받지 않는다. 여러 적이 동시에 닿으면 먼저 처리된 유효 접촉 하나만 피해를 적용한다.
- 군중 이동 후 XZ 중심 거리와 기존 Body Radius + Player Radius로 접촉을 검사한다. 이동의 정지 오차를 고려해 0.002의 허용 오차를 포함한다. 물리 Collider나 밀어내기는 추가하지 않는다.
- IDamageable은 `TakeDamage(float damage)`만 정의한다. PlayerHealth와 EnemyHealth가 구현하고, EnemyMovement와 MagicProjectile은 인터페이스로만 피해를 전달한다. 소수점 피해를 그대로 전달하며 기존 피해량 10과 체력 설정은 유지한다.
- 체력은 0 아래로 내려가지 않는다. PlayerHealth는 HP 0에서 사망 상태를 기록하고 알린다. 게임 종료 상태, 시간 정지, 플레이어 제거와 씬 복귀는 GameManager가 관리한다.
- 플레이어 발밑 HP 바는 PlayerHUD의 Screen Space Overlay Canvas에서 표시한다. PlayerHPBar가 기존 IObserver를, PlayerHealth가 ISubject를 구현한다. HP 비율은 활성화 시와 체력 변경 Notify 알림 때만 갱신하고, 발 위치 추적은 LateUpdate에서 처리한다. 사망으로 시간이 정지한 프레임에도 0을 표시한다.
- HP 바는 OnEnable에서 구독하고 OnDisable에서 해제한다. PlayerHealth 초기 체력 설정 때도 알림을 보내 초기화 순서와 관계없이 표시를 맞춘다. 중복 구독은 막으며 피해 간격에 차단된 공격은 알림을 보내지 않는다.
- HP 바 기본 크기는 100×10(Canvas 기준), worldOffset=(0,-1,0), screenOffset=(0,-14)이다. 바의 RectTransform과 스크립트 설정으로 크기·위치를 조절한다. 빨간 전경과 어두운 배경을 사용하고 입력은 받지 않는다.
- 일시 정지 메뉴는 구현했으며 재시작·회복·피격 효과는 아직 구현하지 않는다. 생존 타이머는 아래 규칙으로 구현한다.

### 확정된 카메라 규칙

- 직교(Orthographic) 투영의 월드 Z축 기준 쿼터뷰를 사용한다. 대각선 구도 대신 이 구도로 최종 확정했다.
- 기본 고정 회전은 X=45도, Y=0도, Z=0도이다. 플레이어가 회전해도 카메라 각도는 바뀌지 않는다.
- CameraFollow가 LateUpdate에서 플레이어의 추적 위치로 즉시 이동한다. 플레이어가 이동하면 카메라도 즉시 이동하고, 멈추면 즉시 멈춘다. 추적 보간이나 지연은 사용하지 않는다.
- 시작 시에는 추적 위치에 즉시 배치해 진입 이동을 없앤다.
- 기본 Orthographic Size는 8, 추적 거리는 20이다. 인스펙터에서 구도를 조절할 수 있다.
- 직교 투영의 화면 범위는 Camera의 Size로 조절한다. Distance는 배치 거리이며 확대·축소 값이 아니다.
- 기존 월드 기준 이동을 유지하며 W·↑는 화면 위쪽, D·→는 화면 오른쪽으로 이동한다.
- 이번 범위는 고정 구도와 즉시 추적까지이다.

### 생존 타이머 UI

- 기존 TimeSystem과 TimerUI를 재사용한다. TimeSystem은 경과 시간을 계산하고 분·초가 달라질 때만 ISubject 알림을 보낸다. TimerUI는 IObserver로 구독·해제하고 TextMeshProUGUI에 `00 : 00` 형식으로 표시한다.
- 기본 Start Time은 0초이며 TimeSystem 인스펙터에서 변경해 경계 시간을 테스트할 수 있다. 정수 총 초에서 `/ 60`, `% 60`으로 분·초를 함께 계산한다.
- Time.deltaTime 기반이므로 일시정지·사망으로 Time.timeScale이 0이면 생존 시간도 멈춘다. 현재 단계에서는 실제 전투가 진행되는 시간만 센다.
- HUDCanvas/TimerUI/TimerText의 기존 상단 중앙 배치를 유지한다. 텍스트는 위에서 50만큼 아래, 높이 50, 글자 크기 36이며 이후 경험치 바 아래에 놓을 공간이다.
- 시간 제한 클리어와 결과 화면, 일시 정지 버튼은 GameManager와 각 UI에서 관리한다.

## 4. 적 — 확정 기획

- 플레이어의 화면 밖에서 생성된다.
- 생성된 적은 플레이어를 추적한다.
- 각 적은 체력을 가지며 체력이 0 이하가 되면 사망한다.
- 처치 시 일정 확률로 경험치 보석을 생성한다.
- 진행 시간에 따라 등장하는 종류와 생성량이 달라진다.
- 일반 적은 5종이며 보스는 없다.
- 박쥐 무리는 별도 적 종류가 아니라 기존 박쥐를 짧은 시간 동안 대량 생성하는 이벤트이다.

### 박쥐 이동 — 현재 구현 규칙

- 되돌린 군중 이동 알고리즘을 유지하고 역할만 EnemyMovement와 EnemyCrowd로 분리한다.
- EnemyMovement는 기존 인스펙터 설정, 개별 적 상태, 이동·접근 정지·회전을 담당한다.
- EnemyCrowd는 활성 적 등록, 격자 구성·검색, 이웃 분리·겹침 계산, 전체 시뮬레이션 순서를 담당하는 정적 클래스이다. 별도 컴포넌트를 추가하지 않는다.
- 플레이어 Transform을 인스펙터에 지정한다. XZ 평면에서 추적·좌우 회피·분리 이동·겹침 보정을 수행하며 각 적의 Y는 유지한다.
- 이동 방향과 관계없이 플레이어를 향해 회전한다.
- 코드 기본 이동 속도는 3, 회전 속도는 360도/초이다. GameScene의 기존 설정은 이동 속도 3, 회전 속도 540도/초로 유지한다.
- 적의 자발적인 접근 정지 거리는 Body Radius + Player Radius로 계산한다. GameScene에서는 0.5 + 0.4 = 0.9이다. Player Radius는 실제 Player Collider와 자동 연결되지 않는 이동용 설정값이다.
- 플레이어는 적에게 막히거나 적을 밀지 않고 통과한다. 플레이어 반경 안의 적을 바깥으로 강제 배치하던 LimitApproach는 제거했다. 접근 정지는 추적 속도에만 반영하고, 플레이어와 적의 겹침은 허용한다. 적끼리의 분리와 겹침 보정은 유지한다.
- 접촉 거리까지 남은 간격이 0.001 이하이면 적의 속도와 자발적 이동을 멈춘다. 플레이어가 먼저 겹쳐 들어와도 바깥으로 밀어내지 않는다. 접촉 전에는 속도 보간의 잔여 관성을 포함한 실제 이동량을 남은 간격으로 제한한다. 적끼리 겹침을 해소하기 위한 보정 이동은 계속 허용한다.
- 이전 Separation Distance 0.3은 반경 합에 더하던 여유 거리였다. 현재 Separation Range는 절대 검색 범위이므로 GameScene의 같은 크기 적 기준 1.3으로 이관한다. Separation Strength 1.5는 유지한다.
- Overlap Correction Speed는 3으로 설정한다. 외형·군중 밀도 조정은 이 코드의 인스펙터 설정으로 수행한다.
- 활성화·비활성화 시 적 목록에 등록·해제한다. 추가 관리 오브젝트는 필요 없다.
- LateUpdate에서 한 프레임에 한 번 전체 무리를 계산한다. 큰 프레임 간격은 최대 4개 단계로 나누고 각 단계에서 겹침 보정을 4회 수행한다.
- 기존 2단위 크기의 XZ 격자와 칸별 연결 목록을 사용한다. 검색 범위와 적 반경에 따라 검사할 칸 수를 계산한다.
- 좌우 선호 방향, 속도 보간, 분리 가중치, 적끼리 겹침 보정은 유지한다. 플레이어 접근 제한은 위치 강제 보정 대신 추적 속도를 줄이는 방식이다. 이전 버전의 후보 각도 탐색과 접촉 상태 로직은 사용하지 않는다.
- Collider 기반 물리 충돌이나 복잡한 장애물 경로 탐색은 추가하지 않는다. 극단적인 밀집에서는 잔여 겹침이 남을 수 있다.
- GameScene에 수동 배치된 Bat 오브젝트들로 이동을 검증한다.
- 지팡이 조준·발사·레벨 강화·관통·넉백, 적 체력·피해·사망 처리를 구현했다. 박쥐 무리 이벤트는 아직 구현하지 않았다.

### 화면 밖 적 반환

- EnemyMovement의 Offscreen Return Delay 기본값은 5초이며 씬의 적 또는 Bat 프리팹 인스펙터에서 조절한다.
- Game 카메라(MainCamera)의 viewport와 near/far 범위를 적 중심 기준으로 확인한다. 화면 밖에 연속해서 머문 시간을 누적하고, 제한 시간 전 화면 안으로 돌아오면 0으로 초기화한다.
- EnemySpawner가 카메라와 군중 이동 이후 LateUpdate에서 0.2초마다 활성 적을 일괄 검사한다. EnemyMovement의 개별 Update와 카메라 참조는 제거했다.
- EnemyMovement는 화면 밖 최초 확인 시각과 반환 대기 시간만 보관하고, 스포너는 화면 판정과 반환을 담당한다. Time.time 기준 경과 시간을 사용하므로 일시정지 중에는 누적되지 않는다.
- 반환 시 활성 목록에서 즉시 제거되므로 역순으로 순회한다. 검사 주기는 스폰 간격과 독립적이다.
- 화면 진입·복귀와 반환은 검사 시점에 반영된다. 0.2초 검사 사이에 잠깐 들어왔다 나가는 경우는 놓칠 수 있으며, 저프레임에서는 지연이 더 커질 수 있다.
- 제한 시간 도달 시 기존 ObjectPool로 반환하며, 재활성화 때 타이머를 초기화한다. 씬에 직접 배치된 비풀 소유 적은 기존 사망 처리와 같이 비활성화 후 Destroy한다.
- 화면 밖에서 새로 생성한 적도 이 제한 시간을 적용받는다. 이동 속도와 스폰 거리에 맞춰 대기 시간을 조절한다.

### 풀 데이터 등록·관리

- TryReturnToPool은 풀 소유 객체를 반환하고, 미등록 객체는 ObjectPool 내부에서 비활성화 후 Destroy한다. 반환값은 기존처럼 풀 소유 여부에 따라 true/false이며, 호출부에서 별도 제거를 하지 않는다.

- 씬의 PoolDataInitializer 하나에 PoolData 배열을 모아 등록한다. 현재 Bat와 ExperienceGem 풀의 기존 프리팹·준비 수 15·Parent 설정을 이관했다.
- DefaultExecutionOrder(-200)의 Awake에서 등록해 다른 스크립트의 Start 전에 준비한다. 중복 풀 종류나 누락된 프리팹은 경고 후 건너뛴다.
- 초기화 오브젝트는 자신이 등록한 풀 종류만 기록하고 OnDestroy에서 정리한다. Parent가 비어 있으면 PoolDataInitializer Transform 아래에 풀 오브젝트를 둔다.
- ObjectPool의 Queue 생성·대여·반환 코드는 유지한다. EnemySpawner는 등록·정리를 하지 않고 등록된 적 풀을 사용한다. 투사체 풀링은 추가하지 않는다.

### 기본 적 스폰 — 현재 구현 규칙

- EnemySpawner 하나가 PoolDataInitializer에 등록된 Bat 풀을 사용해 프리팹 한 종류를 생성한다. 시간대별 웨이브나 다른 적 종류는 아직 구현하지 않는다.
- 카메라 추적 이후의 Game 카메라 네 모서리를 적 이동 높이의 평면에 투영한다. 임의의 경계 바깥으로 반경과 여유 거리를 더해 생성한다. 기본 높이는 1, 화면 밖 여유 거리는 2이다.
- 기본 스폰 간격은 1초, 최소 적 수는 15, 최대 적 수는 50이다. Inspector에서 조절한다. 시작 프레임에도 부족한 수를 채운다.
- 활성 EnemyMovement 수를 확인해 최소 수에 부족한 만큼만 생성한다. 최대 수 이상일 때는 생성하지 않으며, 최소 수가 최대 수보다 크면 최대 수로 제한한다. 최대 수를 낮췄다고 기존 적을 제거하지 않는다.
- 기존 씬의 수동 배치 박쥐 3개도 살아 있는 적 수에 포함한다. 이들은 기존처럼 사망 시 Destroy하고, 풀에서 생성한 적만 풀로 반환한다.
- EnemyMovement.SetTarget은 생성된 적에 플레이어 참조를 전달하는 연결 메서드이다. 군중 이동 계산은 유지한다.
- 재활성화 시 EnemyHealth의 체력과 사망 상태를 초기화한다. 피해 계산은 유지하고 풀 소유 적의 사망만 기존 ObjectPool 반환으로 연결한다.
- PoolDataInitializer의 Pools 목록에서 프리팹과 준비 수를 지정하고, EnemySpawner에서는 Enemy Pool Type만 선택한다. 기존 풀 종류에 Bat를 추가했으며, 향후 적 종류는 풀 종류와 프리팹을 추가하고 스포너의 생성 규칙을 확장한다. 별도 웨이브 시스템은 미리 만들지 않는다.

### 마법 지팡이 레벨 1~8 — 현재 구현

- Player의 MagicWand가 지정된 게임 카메라 화면 안의 활성 EnemyMovement 중 가장 가까운 적을 선택한다. 적 중심의 viewport 좌표와 near/far 범위로 화면 안 여부를 판정한다.
- 레벨 1 기본 쿨타임은 1.2초이며 한 번에 1개를 발사한다. 화면 내 대상이 없으면 해당 발사를 생략하고 다음 발사 시점에 다시 탐색한다.
- 발사 순간 적 방향을 저장해 푸른 투사체를 직선 이동시킨다. 발사 후 적을 추적하거나 플레이어를 따라가지 않는다.
- 기본 투사체 속도는 초당 12이며 인스펙터에서 조절한다. 기존 Blue 재질을 사용한 구형 프리팹이다.
- 투사체 중심이 게임 카메라 화면 또는 클리핑 범위를 벗어나면 Destroy한다. Scene 뷰 카메라는 판정에 사용하지 않는다.
- 투사체의 이전 위치부터 다음 위치까지의 선분과 적 중심 사이의 거리를 검사한다. 적 Body Radius와 투사체 Hit Radius(기본 0.125)를 더한 구형 근사 범위에 닿으면 투사체만 Destroy한다. 별도 Collider는 추가하지 않는다.
- 명중 검사는 EnemyCrowd의 격자를 사용한다. 이동 구간의 XZ 경계를 최대 적 반경 + 투사체 반경만큼 확장한 범위의 칸만 순회하고, 후보 적에 기존 3D 선분 거리 검사를 적용한다. 빠른 투사체가 여러 칸을 통과해도 구간 전체를 검사한다.
- 군중의 마지막 겹침 보정 후 최종 위치로 격자를 갱신한다. 등록·해제 직후나 해당 프레임에 아직 갱신되지 않은 경우 첫 명중 조회에서 현재 위치로 갱신한다. 투사체마다 배열이나 후보 목록을 생성하지 않는다.
- 군중 이동 계산과 투사체 직선 이동·화면 밖 제거 규칙은 유지한다. 관통 횟수를 소진하면 제거한다. 투사체는 LateUpdate에서 처리한다.
- 적의 EnemyHealth에서 Max Health 기본값 5, 무기의 MagicWand에서 기본 Damage 10을 인스펙터에서 조절한다. 투사체는 발사 시 피해량·관통·넉백을 복사하며 이후 강화의 영향을 받지 않는다.
- 체력은 0 미만으로 내려가지 않는다. 체력 0이면 즉시 비활성화해 조준·군중 목록에서 제외한다. 풀 소유 적은 반환하고 그 외 적은 Destroy한다. 같은 프레임의 중복 사망 처리는 막는다.
- 이동 구간에 여러 적이 있으면 구형 판정 범위의 최초 접촉 시점이 가장 이른 적을 선택한다. 적 이동과 기존 격자 검색은 유지한다.
- 관통과 무기 강화는 구현했으며 투사체 오브젝트 풀링은 아직 적용하지 않는다.
- 초기 피해량 10, 연사 간격 0.1초, 투사체 수 1, 넉백 강도 1, 관통 1이다. 관통은 타격 가능한 적의 총수로, 초기에는 첫 명중에 사라진다.
- 레벨 효과: 2레벨 투사체 +1, 3레벨 쿨타임 -0.2초, 4레벨 투사체 +1, 5레벨 피해량 +10, 6레벨 투사체 +1, 7레벨 관통 +1, 8레벨 피해량 +10. 최대 레벨은 8이다.
- Weapon이 보유 여부·레벨·기본 피해량·투사체 수·넉백·쿨타임 감소를 공통 관리한다. 경험치 구독은 GameManager만 담당하고 무기의 자동 강화 구독은 제거했다. Weapon.LevelUp()이 레벨을 증가시킨 후 protected virtual UpgradeWeapon(int level)을 호출하고, 각 무기의 override가 능력치를 직접 변경한다. 능력치 프로퍼티에는 레벨 조건식을 두지 않는다. 획득은 항상 레벨 1로 시작하며 재활성화 시 강화를 중복 적용하지 않는다. 공격 주기·방식은 파생 클래스가 담당한다. MagicWand의 기존 직렬화 필드 이름은 유지한다.
- 쿨타임은 연사 시작부터 다음 연사 시작까지다. 각 발사 순간 화면 내 가장 가까운 적을 재탐색하며 대상이 없으면 해당 발사를 생략한다. 연사 도중 강화되어도 예약 발사 수는 유지하고, 각 투사체 능력치는 실제 발사 시점의 값을 복사한다. 진행 중인 쿨타임은 소급 변경하지 않는다.
- 조준은 발사 시에만 EnemyCrowd의 활성 적 목록을 인덱스로 순회한다. 씬 전체 검색이나 검색용 배열 생성은 하지 않는다. 정확한 화면 내 최단 거리 선택을 위해 활성 후보는 순회하되, 현재 최단 거리보다 먼 후보는 화면 좌표 변환을 생략한다.
- 연사 중에도 쿨타임이 감소하며 0 아래로 누적되지 않는다. 연사가 쿨타임보다 길면 기존 연사를 끝낸 뒤 다음 프레임에 새 연사를 시작한다. 연사는 중첩하지 않고 종료 시점에 쿨타임을 다시 추가하지 않는다.
- 기존 격자 기반 이동 구간 검색에서 이미 맞힌 적을 제외해 접촉 순서대로 처리한다. 한 프레임에 여러 적을 통과해도 관통 횟수만큼 처리하며 동일 투사체는 같은 적에게 재명중하지 않는다.
- 넉백 1은 기본 1유닛을 0.15초 동안 밀어낸다. EnemyMovement의 Knockback Distance/Duration에서 조절하며 강도는 거리에 곱한다. XZ 이동과 Y 유지를 지키고, 밀리는 동안 추적만 잠시 중단한다. 기존 겹침 보정과 플레이어 방향 회전은 유지하므로 밀집 상태에서는 실제 변위가 줄어들 수 있다. 재명중은 방향·시간을 갱신하고 풀 반환·재사용 시 초기화한다.

#### 무기 강화 테스트

- Play Mode에서 MagicWandWeapon 컴포넌트 메뉴의 Level Up (Play Mode)로 보유 무기만 수동 강화할 수 있다. 일반 플레이는 플레이어 레벨업 선택 UI를 통해 선택한 무기만 강화한다. 프리팹의 Level을 테스트용으로 올리지 않는다. 획득은 항상 레벨 1이며, Play 중 생성된 보유 인스턴스의 Level Up 메뉴를 사용한다. 실행 중 Level 필드만 변경하는 것은 강화 적용을 호출하지 않는다.
- 기본값 기준 (피해량/투사체 수/쿨타임/관통): LV1 10/1/1.2/1, LV2 10/2/1.2/1, LV3 10/2/1.0/1, LV4 10/3/1.0/1, LV5 20/3/1.0/1, LV6 20/4/1.0/1, LV7 20/4/1.0/2, LV8 30/4/1.0/2. 레벨 8 이후 강화는 무시한다.
- 기본 적은 HP 5라 한 방에 죽는다. 넉백·중복 명중 테스트 시 Bat 프리팹 Max Health를 임시로 100 이상으로 높이고, 넉백 후 추적 재개·Y 유지·일시 정지·풀 재사용을 확인한다. 이후 HP를 5로 복원한다.

### KingBibleWeapon — 원형 회전 무기

- Weapon을 상속하며 MagicWand와 별도의 레벨·타이머로 독립적으로 공격한다. GameScene Player의 WeaponManager에 무기 프리팹을 등록한다. 시작 시 MagicWand만 생성하고 KingBible은 획득 전까지 생성하지 않는다. 레벨업 선택 UI에서 KingBible을 처음 선택하면 레벨 1로 획득한다.
- 기본 피해량 10, 큐브 수 1, 쿨타임 3초, 지속시간 3초, 재피격 제한 1.7초, 넉백 강도 1이다. 공격 종료 후 쿨타임을 시작하므로 기본 주기는 3초 회전 → 3초 대기다. 최초 공격은 즉시 시작한다.
- 기본 범위 100%는 회전 반지름 2유닛, 속도 100%는 초당 180도다. 증가율은 기본값에 합산하며 레벨 6에서는 범위 150%(3유닛), 속도 160%(초당 288도)다. Inspector의 Orbit Radius/Rotation Speed로 기본값을 바꿀 수 있다.
- 레벨 2: 큐브 +1, 3: 속도 +30%·범위 +25%, 4: 지속시간 +0.5초·피해량 +10, 5: 큐브 +1, 6: 속도 +30%·범위 +25%, 7: 지속시간 +0.5초·피해량 +10, 8: 큐브 +1. 최대 레벨에서 피해량 30, 큐브 4개, 지속시간 4초다.
- 공격 시작 시 큐브 수·피해량·넉백·반지름·회전 속도·지속시간·재피격 제한을 확정한다. 도중 강화는 다음 공격에 반영한다. 대기 시간은 공격 종료 시의 Cooldown을 사용한다.
- BibleProjectile은 한 변 0.6인 큐브 프리팹이다. XZ 평면에서 플레이어 중심의 원 둘레에 360/N도 간격으로 배치하며 높이는 플레이어 중심을 따른다. 범위 강화는 반지름에만 적용하고 큐브 크기와 Hit Radius(기본 0.3)는 유지한다. Collider는 추가하지 않고 구형 근사 판정을 사용한다.
- KingBible이 원호와 플레이어 이동 경로를 약 0.1유닛 이하의 짧은 구간으로 나누고, BibleProjectile은 각 이동 구간에서 EnemyCrowd의 기존 격자를 조회한다. 모든 명중 후보에 IDamageable 피해와 기존 넉백을 전달한다. 적 군중 알고리즘은 변경하지 않는다.
- 재피격 제한은 KingBibleWeapon 하나가 모든 큐브에 걸쳐 공유한다. 같은 적은 어느 큐브에 닿아도 마지막 명중 후 1.7초가 지나야 다시 피해를 받으며 공격이 끝나도 남은 제한을 유지한다. 다른 무기의 명중은 제한하지 않는다.
- EnemyMovement의 ActivationVersion은 활성화마다 증가한다. 풀에서 재생성한 적은 이전 생명의 재피격 제한을 이어받지 않는다. 만료·비활성 적의 기록은 다음 공격 시작 시 정리한다.
- 큐브는 필요한 수만 생성하고 공격 종료 시 비활성화해 다음 공격에서 재사용한다. 공용 ObjectPool은 변경하지 않는다. 플레이어 제거 시 자식 큐브도 함께 제거하며, 무기 비활성화 시 큐브를 숨긴다. 일시 정지 중 회전·지속시간·쿨타임·재피격 제한 시간은 멈춘다.

#### KingBibleWeapon 테스트

- GameScene에서 MagicWand와 KingBible의 동시 공격, 플레이어 이동 중 원 중심 추적, 기본 3초 회전/3초 대기를 확인한다.
- 각 무기의 Level Up (Play Mode) 메뉴로 독립 강화와 균등 배치를 확인한다. 특정 시작 레벨은 Play 전에 Level 필드로 설정한다. LV2에서 2개, LV5에서 3개, LV8에서 4개다. LV3/6의 범위·속도와 LV4/7의 피해·지속시간 증가도 확인한다.
- 재피격 테스트 시 Bat의 Max Health를 임시로 100 이상으로 높이고 MagicWand를 잠시 비활성화해 피해를 구분한다. 큐브 여러 개가 닿아도 같은 적에 대한 피해는 1.7초 내 한 번이며, 다른 적은 즉시 피해를 받는다. 풀 재사용 시 첫 명중이 즉시 가능한지도 확인한다.
- 정지·재개, 게임 오버 시 큐브 제거, 게임 클리어 시 정지, 재시작 시 레벨과 타이머 초기화를 확인한다. 테스트 후 적 HP와 무기 활성 상태를 복원한다.

### 경험치 보석 드롭 — 현재 구현 범위

- EnemyHealth에서 사망이 확정된 직후, 적 반환/제거 전에 사망 위치의 XZ 좌표에 보석 1개를 확률적으로 생성한다.
- Gem Drop Chance 기본값은 0.6(60%)이며 Inspector에서 0~1로 수정한다. 중복 사망 호출은 보석을 중복 생성하지 않는다. 화면 밖 반환은 사망이 아니므로 드롭하지 않는다.
- ExperienceGem 프리팹은 기존 Blue 재질의 Sphere이며 지름은 0.3이다. SphereCollider의 Is Trigger를 사용한다. ExperienceGem이 XP 값·접촉 획득·풀 반환을 담당한다. 별도 Rigidbody는 추가하지 않고 플레이어의 기존 CharacterController와 접촉한다.
- Ground Layers(기본 Ground 레이어)를 아래 방향 Raycast로 검사하고, 바닥 높이 + Sphere 반높이에 중심을 배치한다. 현재 바닥 Y=0에서는 보석 중심 Y=0.15이다. 바닥을 찾지 못하면 공중에 생성하지 않는다.
- PoolDataInitializer가 보석 풀을 등록·정리하며 ObjectPool의 ExperienceGem 종류로 생성한다. 적 스폰 규칙과 기존 사망·피해 계산은 유지한다.
- 보석의 기본 Experience Value는 1 XP이며 프리팹 Inspector에서 수정한다. 플레이어 접촉 시 경험치를 지급하고 기존 ObjectPool에 반환한다. 시간 경과 제거는 추가하지 않는다.

## 7. 경험치와 레벨업 — 확정 기획

1. 적을 처치하면 일정 확률로 경험치 보석이 생성된다.
2. 플레이어가 보석을 획득하면 경험치가 증가한다.
3. 일정량의 경험치가 쌓이면 레벨업한다.
4. 레벨업 시 게임을 일시정지하고 선택 UI를 표시한다.
5. 플레이어가 선택지 중 하나를 선택한다.
6. 새 무기 또는 장신구를 획득하거나, 기존 무기 또는 장신구를 강화한다.
7. 선택 효과를 적용하고 게임을 재개한다.

### 현재 구현된 획득·자동 레벨업

- PlayerExperience는 레벨 1, 현재 XP 0으로 시작한다.
- 기본 필요 XP는 5, 15, 25, 35…이다. 해당 레벨에서 다음 레벨로 가는 데 필요한 양이며 총 누적 XP가 아니다.
- First Level Requirement(기본 5)와 Experience Increase Per Level(기본 10)을 Inspector에서 조절한다. 수식은 `첫 필요량 + (현재 레벨 - 1) × 증가량`이다.
- 플레이어 CharacterController가 보석 SphereCollider Trigger에 닿으면 ExperienceGem.OnTriggerEnter에서 PlayerExperience에 XP를 전달한다.
- ExperienceGem 전용 레이어(10)는 Player 레이어(8)와만 상호작용한다. 물리적으로 막거나 밀지 않는다. 프리팹의 Radius 0.5와 Scale 0.3으로 실제 보석 반경은 기존과 같은 0.15이다.
- PlayerExperience의 전체 보석 순회와 직접 캡슐·거리 계산, ExperienceGem의 활성 목록을 제거했다. 경험치 누적·레벨업 계산은 그대로 유지한다.
- 보석은 획득 상태를 먼저 기록해 중복 이벤트의 XP 지급을 막고 풀로 반환한다. 재활성화 시 획득 상태를 초기화한다. 일시정지·게임 종료 중에는 획득하지 않는다.
- 필요 XP가 충족되면 자동 레벨업하고 초과 XP는 이월한다. 한 번에 큰 XP를 얻으면 여러 레벨을 연속 처리한다.
- 플레이어 레벨업은 아래 무기 선택 UI에 연결한다. 장신구 선택·강화는 아직 추가하지 않는다.
- 선택지 개수와 구성 규칙은 추후 결정한다.

### 경험치·레벨 UI

- 기존 HUDCanvas/ExperienceUI의 Slider와 오른쪽 LevelText 배치를 사용한다. 경험치 비율은 `현재 XP / 현재 레벨의 필요 XP`, 레벨은 공백 없이 `LV1`, `LV2` 형식으로 표시한다.
- PlayerExperience가 기존 ISubject를 구현하고, ExperienceUI가 IObserver로 구독한다. OnEnable에서 구독·초기 표시하고 OnDisable에서 해제한다. 별도 매 프레임 UI 갱신은 하지 않는다.
- 유효한 XP 획득 처리가 끝나면 최종 상태를 한 번 알린다. 한 번에 여러 레벨이 올라가도 최종 레벨과 잔여 XP를 표시한다. 0 이하 XP는 알림을 보내지 않는다.
- Slider는 표시 전용으로 직접 조작할 수 없으며 값은 0~1을 사용한다. 무기 선택 UI는 GameManager와 LevelUpUI가 별도로 관리한다.

## 8. 장신구 — 확정 기획

### 공통 규칙

- 장신구는 총 5종이며 각각 최대 레벨은 5이다.
- 획득 즉시 효과를 적용한다.
- 같은 장신구를 다시 선택하면 레벨이 증가한다.
- 효과는 해당 플레이가 종료될 때까지 유지된다.
- 최대 레벨에 도달한 장신구는 레벨업 선택지에서 제외한다.
- 초기 구현에서는 해금 조건과 무기 진화를 제외한다.
- 아래 수식의 `L`은 해당 장신구 레벨이며, 미보유 상태는 0이다.

### 검은 심장 (Hollow Heart)

- 강화 능력치: 최대 체력
- 레벨당 **현재 최대 체력을 기준으로 20% 누적 증가**한다.
- 최대 체력이 증가해도 현재 체력은 자동으로 회복되지 않는다.
- 다른 최대 체력 효과가 없는 경우: `기본 최대 체력 × 1.2^L`
- 기본 최대 체력이 100이면 레벨 1에서 120, 레벨 5에서 248.832이다.
- 현재 체력이 `70/100`일 때 첫 획득 후에는 `70/120`이 된다.
- 소수점 처리 방식은 구현 전에 확인한다.

### 시금치 (Spinach)

- 강화 능력치: 모든 무기의 공격력
- 레벨당 공격력 보너스 10%, 최대 50%이다.
- 마법 지팡이, 채찍, 단검, 원형 범위 공격에 공통 적용한다.
- 수식: `기준 공격력 × (1 + 0.1 × L)`
- 기준 공격력 10, 레벨 3이면 최종 공격력은 13이다.
- 무기 자체의 레벨 강화와 결합할 때 사용할 기준 공격력은 구현 전에 확인한다.

### 빈 책 (Empty Tome)

- 강화 능력치: 모든 무기의 공격 쿨다운
- 레벨당 쿨다운 감소 8%, 최대 40%이다.
- 수식: `기본 공격 쿨다운 × (1 - 0.08 × L)`
- 기본 공격 주기 1초, 레벨 3이면 최종 공격 주기는 0.76초이다.
- 연속 발사 내부 간격과 원형 공격의 피해 간격까지 적용하는지는 구현 전에 확인한다.

### 날개 (Wings)

- 강화 능력치: 이동 속도
- 레벨당 이동 속도 보너스 10%, 최대 50%이다.
- 수식: `기본 이동 속도 × (1 + 0.1 × L)`
- 기본 이동 속도 5, 레벨 3이면 최종 이동 속도는 6.5이다.

### 매혹의 오브 (Attractorb)

- 강화 능력치: 경험치 보석 획득 범위
- 레벨당 획득 범위 보너스 20%, 최대 100%이다.
- 수식: `기본 획득 범위 × (1 + 0.2 × L)`
- 기본 획득 범위 2, 레벨 3이면 최종 획득 범위는 3.2이다.
- 획득 범위의 거리 판정과 보석의 즉시 획득·끌어당김 방식은 구현 전에 확인한다.

검은 심장은 누적 곱셈이고, 나머지 네 장신구의 레벨 보너스는 기본값 기준 합산이다.

## 9. 권장 개발 순서 — 미확정 제안

짧은 플레이에서도 핵심 순환이 연결되도록 만든 후 콘텐츠를 늘리는 순서이다. 이 순서 자체가 전체 구현 요청은 아니다.

| 단계 | 범위 | 완료 기준 |
| --- | --- | --- |
| 1 | 플레이어 이동, 바라보는 방향, 카메라, 임시 바닥 | WASD·방향키로 이동하며 전투 공간 확인 |
| 2 | 적 1종 생성·추적, 플레이어 체력, 접촉 피해, 패배 | 화면 밖 생성과 추적, 체력 0에서 종료 |
| 3 | 마법 지팡이, 적 체력·사망 | 가장 가까운 적을 자동 공격하고 처치 |
| 4 | 경험치 보석, 레벨업, 선택 UI, 지팡이 강화 | 처치 → 경험치 → 선택 → 전투 재개 연결 |
| 5 | 채찍, 단검, 원형 범위 공격 | 새 무기 획득과 여러 무기의 동시 동작 |
| 6 | 장신구 5종, 레벨 제한, 선택지 제외 | 획득 즉시 능력치 반영 |
| 7 | 적 5종, 시간대별 생성, 박쥐 무리, 승리 | 지정한 구성으로 10분 진행 후 클리어 |
| 8 | HUD, 재시작, 난이도·성장 속도 조정 | 실제 10분 플레이와 결과 확인 |

4단계까지 완성한 시점에 핵심 재미와 성장 속도를 검토하고, 이후 무기와 적 종류를 추가하는 것을 권장한다.

## 10. 추가 결정 사항

모든 항목을 지금 확정할 필요는 없다. 해당 기능을 구현하기 전에 필요한 항목부터 확인한다.

### 10.1 이동과 카메라 — 첫 구현 전

- 스테이지 경계와 이동 가능 범위, 장애물 유무

### 일시 정지 — 구현

- GameManager는 Paused 상태를 관리한다. 화면 오른쪽 중간의 일시 정지 버튼은 Resource/pause-button 스프라이트를 사용한다.
- PauseGame()은 Playing에서만 동작하며 Time.timeScale을 0으로 설정하고 PauseUI 팝업을 표시한다.
- ESC 키도 동일한 정지·재개 메서드를 호출한다. 플레이 중에는 일시 정지하고, 일시 정지 중에는 재개한다. 게임 오버·클리어 상태에서는 무시한다.
- 팝업 왼쪽 종료하기는 ReturnToStartScene(), 오른쪽 계속하기는 ResumeGame()을 Inspector On Click()으로 호출한다.
- ResumeGame()은 Paused에서만 동작하며 팝업을 닫고 Time.timeScale을 1로 복구한다. 타이머와 전투는 정지한 시점부터 이어진다.
- 게임 오버·클리어 시 팝업을 닫고 일시 정지 버튼을 숨긴다. 종료 상태에서는 정지·재개 요청을 무시하며, 같은 프레임 종료 조건은 일시 정지보다 우선한다.
- PauseUI는 패널 표시와 버튼 선택만 담당하고 종료·재개 흐름은 씬의 GameManager가 관리한다.

### 무기 레벨업 선택 UI — 구현

- GameManager가 PlayerExperience를 구독하고 마지막 확인 레벨과 현재 레벨의 차이를 pendingChoices에 누적한다. 경험치 증가만으로는 선택 횟수가 늘지 않는다. Weapon은 경험치를 구독하지 않으며 자동 강화하지 않는다.
- 시작 무기는 기존 MagicWandWeapon 클래스(마법 지팡이)다. Weapon의 IsOwned는 실행 중 상태이며 Inspector 설정이 아니다. 미보유 프리팹의 표시 레벨은 0이다. KingBible은 미보유로 시작하며 처음 선택하면 Acquire()로 레벨 1부터 공격한다. 이미 보유한 무기는 LevelUp()으로 한 단계만 강화한다.
- 레벨업 후 GameManager는 LateUpdate에서 종료 조건을 먼저 확인하고 ChoosingUpgrade로 전환해 Time.timeScale을 0으로 설정한다. 10분 도달과 사망이 같은 프레임이면 기존 클리어 우선 규칙을 유지한다.
- LevelUpUI는 화면을 어둡게 덮는 패널, 금색 테두리·보라색 배경 창, 제목과 세로 카드 2개를 사용한다. 모든 텍스트는 기존 한국어 폰트의 TextMeshProUGUI다. 카드에는 무기 이름, 미보유이면 신규 · Lv.1, 보유이면 선택 후 적용될 Lv.다음, 획득 또는 다음 강화 설명을 표시한다.
- WeaponManager의 Weapon Prefabs 목록에서 최대 레벨 8인 보유 무기를 제외한다. 후보가 카드 수 이하면 모두 표시하고 더 많으면 중복 없이 무작위로 추린다. 선택 가능한 무기가 하나라면 카드 하나만 중앙에 표시한다. 등록된 모든 무기가 최대 레벨이면 선택 UI를 표시하지 않고 대기 선택 횟수를 비운 뒤 계속 진행한다.
- 카드 Button On Click()은 Inspector에서 GameManager.ChooseWeapon(int)으로 연결한다. 현재 카드 인덱스는 0과 1이다. UI는 흐름을 관리하지 않고 표시·정렬·선택 포커스만 담당한다.
- 여러 레벨이 한 번에 오르면 선택 한 번마다 대기 횟수를 하나씩 차감하고 다음 후보를 갱신한다. 선택 기회가 남으면 시간을 재개하지 않고 다음 선택으로 이어지며, 마지막 선택 후 패널을 닫고 Time.timeScale을 1로 복구한다.
- 선택 중 ESC와 일시 정지·계속하기 요청은 무시하고 일시 정지 버튼을 숨긴다. 기존 일시 정지 중 받은 레벨업은 재개 후 처리한다. 게임 오버·클리어 시 선택 패널과 대기 횟수를 정리하며 종료 후 선택 클릭은 무시한다.
- 세 번째 카드를 추가하려면 LevelUpUI의 Cards 배열에 같은 구성의 카드와 TMP 참조를 추가하고 On Click() 인덱스를 2로 지정한다. 카드 간격은 Card Spacing으로 조절하며 현재 140이다. 추가 무기는 Player의 WeaponManager → Weapon Prefabs 배열에 프리팹을 등록한다. 장신구는 이번 범위에 포함하지 않는다. 아이콘 표시 슬롯은 준비되어 있다.

#### 선택 UI 테스트

- 기본 설정에서 5 XP를 모으면 게임이 멈추고 Magic Wand Lv.2와 King Bible 신규 · Lv.1가 표시되는지 확인한다. 지팡이를 고르면 지팡이만 LV2가 되고, 성경을 처음 고르면 성경 LV1이 시작돼야 한다.
- 빠른 테스트는 PlayerExperience의 First Level Requirement를 1, Experience Increase Per Level을 0으로 임시 설정한다. 연속 선택과 각 무기의 최대 레벨 제외를 확인하고, 이후 각각 5와 10으로 복원한다.
- Play 중 Player 아래 생성된 MagicWand의 Level Up 메뉴로 레벨 8까지 강화하면 다음 선택에서 성경 카드 하나만 중앙에 표시돼야 한다. 성경을 획득하고 두 인스턴스를 모두 8로 강화하면 다음 레벨업은 선택 없이 진행돼야 한다. 재시작하면 지팡이 레벨 1만 보유한다.
- 한 번의 AddExperience 호출로 여러 레벨이 오르면 해당 횟수만큼 선택이 이어지고 중간에 시간이 재개되지 않는지 확인한다. 기본 필요 XP에서 AddExperience(45)는 3회의 선택 기회를 만든다.
- 선택 중 ESC·일시 정지 버튼으로 게임이 재개되지 않는지, 사망·10분 종료 시 선택 UI가 겹치지 않는지, StartScene 복귀 후 새 게임의 보유·레벨·대기 선택 횟수가 초기화되는지 확인한다.

### 무기 선택 카드 표시·아이콘

- 카드 표시명은 Magic Wand / King Bible이다. 보유 무기는 선택 후 적용될 레벨만 Lv.2 형식으로 표시하고, 신규는 신규 · Lv.1로 표시한다.
- 설명은 각 무기의 GetChoiceDescription()에서 다음 레벨을 기준으로 제공한다. 투사체 +1은 지팡이의 경우 "투사체를 1개 더 발사합니다.", 성경은 "투사체를 1개 더 생성합니다."로 표시한다. 쿨타임·피해량·관통·회전 속도·범위·지속시간도 강화 수치를 문장으로 표시한다. 실제 강화 로직은 UpgradeWeapon()을 유지한다.
- Weapon의 Icon 필드에 Sprite를 지정하면 LevelUpUI 카드의 Image에 자동 반영한다. 미지정 상태는 아이콘 Image만 숨기고 테두리와 빈 슬롯은 유지한다. 새 무기는 DisplayName/GetChoiceDescription을 구현하고 Icon을 지정하면 같은 UI를 재사용한다. 카드마다 설명을 직접 입력할 필요가 없다.

### 무기 프리팹과 WeaponManager — 구현

- 무기는 Assets/Prefabs/MagicWand.prefab, KingBible.prefab으로 관리한다. Player에는 개별 무기 컴포넌트 대신 WeaponManager를 배치한다. 프리팹은 무기 스크립트·기본 능력치·아이콘·투사체 프리팹을 보관한다.
- WeaponManager는 Starting Weapon과 Weapon Prefabs를 SerializeField로 참조하고, 프리팹을 키로 보유 인스턴스를 Dictionary에 저장한다. Starting Weapon도 Weapon Prefabs 목록에 등록한다. 시작 무기와 신규 획득은 같은 AcquireOrUpgrade 경로를 사용한다.
- 신규 선택이면 해당 프리팹을 플레이어 아래에 생성하고 로컬 위치 0·로컬 회전 identity로 맞춘 뒤 Acquire()로 레벨 1을 부여한다. 재선택은 기존 인스턴스의 LevelUp()만 호출하므로 오브젝트가 중복 생성되지 않는다. 프리팹 자체의 능력치는 변경하지 않는다.
- 미보유 선택지는 프리팹을, 보유 선택지는 해당 인스턴스를 UI에 전달해 기존 이름·아이콘·신규·다음 레벨·설명을 재사용한다. 무기 타입 enum, 문자열 식별자, 별도 데이터 클래스나 ScriptableObject는 추가하지 않는다.
- GameManager는 경험치 선택 횟수·게임 상태·정지·재개만 관리하며, 후보 구성과 획득·강화는 WeaponManager에 요청한다. LevelUpUI와 기존 버튼 연결은 유지한다.
- 무기 프리팹은 씬 카메라 참조를 저장하지 않는다. WeaponManager가 카메라를 지정하거나 Camera.main으로 찾은 뒤 초기화 시 무기에 전달한다. 무기 루트는 플레이어 자식이므로 중심을 따라가고, 성경의 큐브는 무기의 자식으로 함께 정리된다. 무기 획득용 풀은 추가하지 않는다.
- 새 무기 추가: Weapon을 상속한 공격·UpgradeWeapon·DisplayName·GetChoiceDescription을 구현하고 루트 위치 0·회전 identity·Scale 1인 활성 프리팹을 만든다. 기본 능력치·투사체·Icon을 지정한 뒤 WeaponManager의 Weapon Prefabs에 등록하면 선택 대상에 포함된다. GameManager나 LevelUpUI의 무기별 분기는 추가하지 않는다.
- 등록 중복·빈 항목은 후보에서 제외한다. 후보가 카드보다 많을 때만 일부 추첨하므로 뒤에 등록한 무기도 선택될 수 있다. 모든 보유 무기가 최대 레벨이면 기존처럼 선택 UI 없이 계속 진행한다.

#### 프리팹 관리 테스트

- 시작 직후 Player 아래에는 MagicWandWeapon 인스턴스 하나만 생성되고 KingBible은 없어야 한다. 성경 신규 선택 후 KingBibleWeapon 인스턴스가 하나 생성되고, 재선택은 같은 인스턴스의 레벨만 증가해야 한다.
- 강화 후 프리팹 에셋의 Damage·Projectile Count 등이 바뀌지 않는지, 재시작 시 지팡이만 레벨 1로 생성되는지 확인한다.
- 세 번째 무기 프리팹을 등록하면 후보가 3개일 때 카드 2개에 중복 없이 추첨되는지 확인한다. 같은 프리팹을 중복 등록하거나 빈 항목을 추가해도 선택지 수가 잘못 늘지 않아야 한다.

### KnifeWeapon — 단검 구현

- Weapon을 상속하며 WeaponManager에 KnifeWeapon.prefab을 등록했다. 시작 무기는 지팡이를 유지하고 단검은 레벨업 선택으로 획득한다. 등록 무기가 3개이므로 카드 2개에는 무작위로 추린 후보가 표시된다. 표시명은 Knife, 신규·다음 레벨·강화 설명은 기존 LevelUpUI를 재사용한다.
- 기본 쿨타임 1초, 연사 간격 0.1초, 피해량 6.5, 투사체 수 1, 관통 1, 넉백 0.5다. 관통은 타격 가능한 적의 총수이므로 기본은 한 적 명중 후 제거다.
- PlayerMovement.LastMoveDirection은 마지막 유효 이동 입력을 XZ 평면에서 정규화해 제공한다. 8방향으로 반올림하지 않아 키보드 대각선과 아날로그 360도 방향을 지원한다. 정지 입력은 마지막 방향을 변경하지 않으며 이동 전에는 플레이어 초기 전방을 사용한다. 캐릭터의 부드러운 시각적 회전은 그대로 유지한다.
- WeaponManager가 PlayerMovement.LastMoveDirection을 읽어 각 무기에 전달하며 KnifeWeapon은 발사 순간 전달받은 AttackDirection을 복사한다. 연사 중 입력 방향이 바뀌면 다음 투사체부터 반영하며, 발사 후에는 방향을 바꾸거나 적을 추적하지 않는다. 적이 없어도 발사한다.
- 쿨타임은 연사 시작 기준이다. 긴 연사는 중첩하지 않고 끝낸 뒤 다음 연사를 시작한다. 무기별 타이머는 독립적이며 정지 중에는 발사·쿨타임·투사체 이동이 멈춘다.
- 속도 100%는 초당 12유닛, 범위 100%는 프리팹 크기와 명중 반경의 배율 1이다. Projectile Speed, Speed Multiplier, Area Multiplier로 조절한다. 범위 배율은 투사체 크기와 Hit Radius에 함께 적용하고 자동 조준이나 발사 거리는 변경하지 않는다.
- KnifeProjectile.prefab은 흰색의 길쭉한 큐브(0.12×0.12×0.6)이며 앞쪽은 로컬 +Z다. 별도 투사체 클래스 없이 MagicProjectile의 직선 이동·격자 이동 구간 명중·관통·넉백·화면 밖 Destroy를 재사용한다. 명중은 기본 Hit Radius 0.125의 구형 근사다.
- IDamageable.TakeDamage, Weapon.Damage, 투사체 피해량, 성경의 공격 시 피해량 복사, 적 접촉 피해를 float으로 통일했다. 플레이어·적 체력은 기존 float을 유지하며 소수점 반올림·정수 변환을 하지 않는다. 기존 무기의 10·20·30 피해와 접촉 피해 간격·사망 처리는 유지한다.

#### 단검 테스트

- 레벨업 선택에서 Knife를 획득한 뒤 상하좌우·대각선으로 이동해 투사체가 입력 방향으로 발사되는지 확인한다. 빠르게 방향을 바꿔 캐릭터 회전 중에도 단검이 정확한 입력 방향으로 나가는지 확인한다.
- 정지 후 마지막 방향 유지, 연사 도중 방향 변경, 이동 전 초기 전방 발사, 적이 없어도 발사와 화면 밖 제거를 확인한다. 기존 Input Actions의 Move에는 Gamepad 왼쪽 스틱 바인딩이 있으며 실제 게임패드로 임의 각도도 확인할 수 있다.
- 생성된 KnifeWeapon 인스턴스의 Level Up (Play Mode) 메뉴로 위 표의 수치와 최대 레벨 제외를 확인한다. 단검 피해 확인 시 다른 무기는 잠시 비활성화하고 적 HP를 높여 6.5 피해·넉백 0.5·레벨 5/8 관통을 구분한다.
- 세 무기의 동시 공격, 일시 정지·레벨업 선택 중 중단, 재개, 사망·재시작 후 정리를 확인한다. 테스트 후 임시 HP와 무기 활성 상태를 복원한다.

### 무기 정보 전달과 명명 규칙

- 직선 투사체 클래스·파일은 Projectile로 통일한다. MagicWandWeapon과 KnifeWeapon이 동일한 Projectile을 사용하고, 서로 다른 외형 프리팹(MagicProjectile.prefab, KnifeProjectile.prefab)은 유지한다. 공전용 BibleProjectile은 분리한다.
- 무기 클래스·파일은 MagicWandWeapon, KingBibleWeapon, KnifeWeapon으로 Weapon 접미사를 통일한다. 기존 스크립트 .meta GUID와 프리팹 에셋 이름·GUID는 유지하며 표시명은 변경하지 않는다.
- WeaponManager는 PlayerMovement, Attack Origin, Game Camera를 SerializeField로 참조한다. 비어 있으면 같은 오브젝트의 PlayerMovement, 자신의 Transform, Camera.main을 사용한다. GameScene의 참조는 연결되어 있다.
- 무기 생성 후 Acquire 전에 Weapon.Initialize(Transform, Camera, Vector3)를 호출한다. 무기는 전달받은 AttackOrigin·TargetCamera·AttackDirection을 사용하며 PlayerMovement나 WeaponManager를 직접 참조하지 않는다.
- WeaponManager.Update가 최신 이동 입력 방향을 모든 보유 무기에 전달한 뒤 각 무기의 LateUpdate가 공격한다. 방향은 XZ 평면으로 정규화하며 0 입력은 이전 방향을 유지한다. 별도 정보 클래스·인터페이스나 무기별 관리자 분기는 추가하지 않는다.
- 지팡이는 전달받은 원점에서 적을 조준하고, 단검은 전달받은 방향으로 발사하며, 성경은 전달받은 원점을 중심으로 공전한다. 성경 큐브의 수명 관리를 위한 부모는 기존 무기 Transform을 유지한다.
- 테스트: 세 무기 동시 공격과 방향 전환·정지·정지 후 재개를 확인한다. 단검이 시각적 회전 지연 없이 입력 방향으로 나가는지, 별도 Attack Origin 지정 시 발사·공전 중심이 함께 바뀌는지 확인한다. 기존 획득·레벨업·관통·넉백 수치는 유지한다.

### WhipWeapon — 화면 기준 채찍

- Weapon을 상속한 WhipWeapon과 베기 표시·명중용 WhipSlash를 추가하고 WhipWeapon.prefab을 WeaponManager에 등록했다. 시작 무기는 지팡이를 유지한다. 등록된 네 무기에서 카드 수만큼 추첨한다.
- 기본 피해량 10, 투사체 수(베기 횟수) 1, 쿨타임 1.35초, 연사 간격 0.1초, 범위 배율 1(100%), 넉백 1이다. 투사체 제한 30은 적용하지 않으며 동시 베기 수와 타격 적 수 모두 임의 제한을 추가하지 않는다.
- 공격 축은 TargetCamera.transform.right를 XZ 평면에 투영한 방향이다. 현재 고정 카메라에서는 월드 X축과 일치한다. 캐릭터 회전·전방은 공격 축을 바꾸지 않는다. 상하 방향으로 별도 조준하지 않으며 베기 폭에 해당하는 주변 적만 타격한다.
- 전달받은 AttackDirection을 화면 가로 축과 비교해 마지막 좌우 방향을 유지한다. 상하 입력과 정지는 좌우 방향을 바꾸지 않는다. 채찍이 획득 후 좌우 입력을 받은 적이 없다면 기본은 오른쪽이다.
- 각 연사의 시작 시 가로 축과 첫 공격 방향을 확정하고, 이후 베기는 무조건 이전의 반대편으로 번갈아 발생한다. 연사 도중 이동 방향이 바뀌어도 해당 연사의 교대 순서는 유지하고 다음 연사에 반영한다.
- 쿨타임은 연사 시작 기준으로 흐르며 연사가 더 길면 끝낸 뒤 새 연사를 시작한다. 다른 무기의 공격과 타이머는 독립적이다.
- 기본 길이 3유닛·폭 0.7유닛·표시 시간 0.15초다. WhipWeapon Inspector의 Slash Length/Width/Duration으로 수정한다. 공격 범위 증가는 길이와 폭에 기본값 기준 합산 배율을 곱한다. 베기 중심은 공격 원점을 따라 이동하며 방향은 생성 시 고정한다.
- WhipSlash.prefab은 흰색의 길쭉한 큐브 표시다. 명중 범위는 길이 방향 선분과 폭의 절반 반경으로 구성한 캡슐 근사이며 EnemyCrowd의 기존 격자 검색을 사용한다. Collider와 적 군집 알고리즘은 변경하지 않는다.
- 각 베기의 HashSet으로 동일 베기 내 중복 명중을 제외한다. 서로 다른 베기는 각각 피해·넉백을 줄 수 있다. 원점이 제거되거나 표시 시간이 끝나면 Destroy하며 정지 중에는 수명과 명중 갱신을 멈춘다. 무기의 자식으로 생성해 플레이어 제거 시 함께 정리한다.
- 레벨 2는 베기 +1. 레벨 3~8은 각각 피해량 +5이며, 레벨 4·6은 범위 +10%를 추가한다. 기본값 기준 피해량은 LV1/2 10, LV3 15, LV4 20, LV5 25, LV6 30, LV7 35, LV8 40이다. 범위는 LV4 110%, LV6부터 120%이고 최종 베기 횟수는 2다.

#### 채찍 테스트

- 레벨업 선택에서 Whip을 획득해 좌우·대각선 입력으로 첫 베기 방향이 바뀌는지, 위아래 입력·정지에서는 마지막 좌우 방향을 유지하는지 확인한다.
- LV2에서 0.1초 간격으로 좌→우 또는 우→좌 베기가 발생하는지 확인한다. 연사 도중 방향을 바꿔도 같은 연사의 두 번째 공격은 첫 공격의 반대여야 한다.
- 임시로 다른 무기를 비활성화하고 적 HP를 높여 한 베기에서 같은 적은 한 번만 피해를 받고, 같은 방향에 줄지은 여러 적은 모두 피해를 받는지 확인한다. 화면 위아래로 멀리 떨어진 적은 타격하지 않아야 한다.
- Level Up (Play Mode)로 각 레벨 피해량과 LV4/6 길이·폭 증가, 최대 레벨 제외를 확인한다. 일시 정지·레벨업 선택 중 베기와 수명이 멈추고 재개 후 이어지는지 확인한다. 테스트 후 다른 무기 활성 상태와 적 HP를 복원한다.
