# 3D 생존 게임 기준 기획서

최종 확인: 2026-11-13. 현재 코드·JSON·StartScene·GameScene·프리팹을 기준으로 정리한 문서다. 과거 제안과 중간 구현 이력은 현재 규칙으로 통합했다.

## 1. 문서 사용 원칙

- 앞으로 기능을 하나씩 구현할 때 참고하는 기준 기획서다. 문서의 전체 범위가 한 번의 구현 요청을 의미하지 않는다.
- 아래의 ‘구현’은 코드와 설정이 존재한다는 뜻이다. 실제 Unity 플레이·빌드·성능 검증 완료를 의미하지 않는다.
- 표의 수치는 확인 시점 값이다. 능력치는 JSON, Unity 참조와 배치는 씬·프리팹이 원본이다. 변경 시 이 문서도 함께 갱신한다.
- 코드의 초기값과 씬·프리팹 저장값이 다르면 실제 실행에 사용되는 저장값을 명시한다.
- 장신구 효과 등 이미 확정한 규칙은 임의로 바꾸지 않는다. 새로운 결정이 필요하면 구현 전에 확인한다.

## 2. 게임 목표와 현재 범위

- 장르: Vampire Survivors를 참고한 3D 자동 공격 생존 게임.
- 승리: 게임 내 생존 시간 600초 도달. 패배: 플레이어 HP가 0이 됨.
- 같은 프레임에 사망과 600초 도달이 겹치면 클리어를 우선한다. 보스는 없다.
- 핵심 흐름: 이동 → 화면 밖 적 생성·접근 → 자동 공격·처치 → 경험치 보석 획득 → 레벨업 선택 → 무기·장신구 획득/강화 → 생존.
- 구현 범위: 캐릭터 3종, 일반 적 5종과 이벤트 슬라임, 무기 4종, 장신구 5종, 반복 숲 맵·장애물, 횃불·아이템 3종, HUD·시작·정지·결과 화면, JSON 데이터와 오브젝트 풀.
- 현재 범위에서 제외: 무기 진화, 해금 조건, 보스. 저장·메타 성장·온라인 기능은 구현 대상으로 확정하지 않았다.

## 3. 씬 흐름과 게임 상태

### 시작과 캐릭터 선택

- StartScene에서 TMP의 ‘시작하려면 아무 키나 누르세요’ 문구를 깜빡인다. 현재 시작 입력은 키보드의 새 키 입력이다.
- 입력 후 같은 씬의 캐릭터 선택 패널을 연다. 캐릭터 카드의 이름·시작 무기·고유 능력 설명은 JSON을 사용한다.
- 카드 선택은 배경색으로 구분한다. 표시 시 첫 카드 안토니오를 기본 선택한다.
- 카드 Button On Click은 `CharacterSelectionUI.SelectCharacter(1/2/3)`, 시작 버튼은 `StartGame()`에 연결한다.
- 선택 ID는 DataManager에 유지하고 GameScene에서 기존 플레이어에 적용한다. 캐릭터별 플레이어 생성 팩토리는 사용하지 않는다.

### 플레이·일시 정지·레벨업·결과

- GameManager는 씬에 배치하는 일반 MonoBehaviour다. 필요한 시스템/UI를 SerializeField로 참조한다.
- 상태: Playing / Paused / ChoosingUpgrade / GameOver / Completed.
- TimeSystem이 `Time.deltaTime`으로 생존 시간을 누적한다. 일시 정지·선택·결과 상태는 `Time.timeScale=0`이므로 생존 시간도 멈춘다.
- 오른쪽 중간의 일시 정지 버튼 또는 ESC로 정지한다. 팝업의 왼쪽은 종료하기, 오른쪽은 계속하기다. ESC로도 재개한다.
- 레벨업 선택 중에는 일시 정지 토글을 무시한다. 게임 오버·클리어에서는 정지·재개를 허용하지 않는다.
- GameManager가 LateUpdate에서 600초 도달을 먼저 검사하고, 다음으로 사망 요청을 처리한다. 결과는 한 번만 확정한다.
- 게임 오버는 즉시 게임을 정지하고 GAME OVER 패널을 표시한다. 플레이어 외형의 Die만 UnscaledTime으로 끝까지 재생한 뒤 플레이어를 비활성화·제거한다. Animator가 없으면 기존처럼 즉시 제거한다. 클리어는 플레이어를 유지하고 GAME COMPLETED 패널을 표시한다.
- GameOverUI와 GameClearUI는 분리되어 있으며 결과 시 HP 바와 일시 정지 버튼을 숨긴다.
- 나가기/종료하기 버튼은 Inspector에서 `GameManager.ReturnToStartScene()`을 호출한다. timeScale을 1로 복구한 뒤 StartScene으로 이동한다. 즉시 재시작 전용 버튼은 없다.

## 4. 플레이어와 카메라

- PlayerInput의 `OnMove(InputValue)`로 WASD·방향키 입력을 받는다. W/↑=월드 +Z, D/→=월드 +X다.
- CharacterController로 XZ 이동한다. 자발적인 Y 이동·중력은 추가하지 않는다. 대각선 입력 크기를 제한해 더 빨라지지 않는다.
- 이동 방향으로 부드럽게 회전하며, 멈추면 마지막 방향을 유지한다. LastMoveDirection은 시각적 회전과 별개인 마지막 유효 입력 방향이다.
- 입력 방향을 8방향으로 반올림하지 않아 아날로그 360도 방향을 받을 수 있다. 전체 게임패드 UI 조작 검증을 완료했다는 의미는 아니다.
- 일반 적과 플레이어는 물리 충돌로 서로 막지 않는다. 적은 플레이어 CharacterController의 실제 반경을 사용해 몸체 앞에서 멈춘다. 일반 적이 물리 압력으로 플레이어를 가로지른 경우 이동 구간의 첫 접촉점으로 제한하되, 플레이어가 먼저 들어온 경우 적을 강제로 밀어내지 않는다.
- 카메라는 직교 투영, Z축에 맞춘 고정 쿼터뷰다. GameScene 설정은 각도 (45,0,0), 거리 20, Orthographic Size 10이다.
- CameraFollow는 LateUpdate에서 플레이어 위치에 즉시 맞춘다. 지연·부드러운 추적·회전 입력은 사용하지 않는다.
- CameraFollow는 화면 영역 소비자보다 먼저 실행된다. Game 카메라의 CameraView가 화면 경계 평면과 모서리 Ray를 요청 시 계산하고 같은 프레임에 공유한다. 카메라 행렬이 바뀌면 캐시를 갱신한다. EnemySpawner·TorchSpawner·MapGenerator는 이 결과를 사용하되 생성 높이와 바닥 높이의 교차점은 각각 계산한다.

### 기본 능력치와 피해

- Players.json의 현재 공통 시작값: HP 100, 이동 속도 5, 회전 속도 720, 공통 피해 간격 1초.
- 접촉 피해량은 적 데이터, 피해 간격은 PlayerHealth가 관리한다. 여러 적과 닿아도 플레이어 공통 간격 안에서는 추가 피해를 받지 않는다.
- PlayerHealth와 EnemyHealth는 float 피해량을 받는 `IDamageable.TakeDamage(float)`을 구현한다.
- 체력·경험치·시간 UI는 기존 ISubject / IObserver 알림을 사용한다.

### 캐릭터

| ID | 캐릭터 | 시작 무기 | 고유 능력 |
| --- | --- | --- | --- |
| 1 | 안토니오 | Whip | 플레이어 10레벨마다 모든 무기 피해량 +10%, 최대 +50% |
| 2 | 이멜다 | Magic Wand | 플레이어 5레벨마다 투사체 속도 +10%, 최대 +30% |
| 3 | 젠나로 | Knife | 모든 무기의 투사체 수 +1. 채찍·성경 포함 |

- 안토니오는 시금치와 별도 배율로 곱한다. 최종 피해량 = 무기 강화 후 피해량 × 시금치 배율 × 캐릭터 피해 배율.
- 이멜다의 속도 보너스는 지팡이·단검의 직진 속도와 성경의 공전 속도에 적용한다. 채찍에는 적용하지 않는다.
- 캐릭터 능력은 PlayerCharacter가 레벨 알림으로 갱신하고 WeaponManager가 기존/신규 무기에 전달한다.
- 공통 Player 루트의 이동·충돌·체력·입력·무기와 기존 씬 참조를 유지한다. PlayerCharacter는 시작 시 선택 PlayerData를 저장하고, Inspector의 캐릭터 ID → 외형 프리팹 목록에서 하나를 VisualRoot 아래에 생성한다. 재활성화 시 외형을 중복 생성하지 않는다.
- PlayerMovement는 CharacterController의 실제 XZ 이동량으로 IsMoving을 계산하고 PlayerCharacter가 선택된 외형 Animator에 전달한다. 장애물에 완전히 막히면 Idle로 전환한다. Die Trigger는 게임 오버 확정 시에만 실행하여 같은 프레임의 클리어 우선 규칙을 유지한다. Root Motion은 사용하지 않는다.
- 외형 프리팹은 Assets/Prefabs/Character의 AntonioVisual·ImeldaVisual·GennaroVisual이다. 현재는 캡슐과 정면 표시 및 개별 머티리얼로 구성한 임시 외형이며, 런타임 색상 변경 코드는 없다. 실제 모델·Animator는 각 프리팹 내부에서 교체한다.
- VisualRoot는 Player 로컬 Y=-1, 외형 프리팹은 발 위치를 원점·정면을 +Z로 맞춘다. 외형에는 게임플레이 스크립트·추가 Collider/Rigidbody를 넣지 않으며 Animator 사용 시 Apply Root Motion을 끈다. 모델별 크기·회전 보정은 프리팹 내부에서 관리한다.

## 5. 적과 스폰

### 일반 적

- EnemyMovement는 추상 공통 기반으로 데이터·타깃·등록·접촉 피해·넉백 상태를 담당한다. 일반 적 프리팹에는 EnemyDefaultMovement, 이벤트 프리팹에는 EnemySwarmMovement를 붙인다. 두 클래스는 기반 클래스를 상속한 MonoBehaviour이며 다른 종류로 전환하지 않는다.
- 일반 적은 FixedUpdate에서 동적 Rigidbody 속도로 이동한다. SphereCollider의 월드 반경은 5종 모두 0.45이며 비균일 프리팹 스케일을 보정한다.
- 중력은 끄고 Y 위치와 물리 회전을 고정한다. 이동 방향과 관계없이 플레이어를 바라본다.
- 일반 적끼리와 Obstacle 레이어의 충돌은 Physics가 처리한다. 이전의 일반 적 전체 격자 분리·반복 겹침 보정은 사용하지 않는다.
- 장애물에 실제로 막힌 뒤에만 SphereCast로 좌우 회피를 보조한다. 요청 방향으로 절반 미만 전진하는 상태가 0.15초 누적되면 판단을 시작한다. NavMesh·A*는 사용하지 않는다.
- 회피 탐색 반경에는 0.02 여유를 주되 실제 Collider 반경은 유지한다. 넉백은 이동 구간을 검사해 장애물 관통을 제한한다.
- 복잡하게 막힌 지형에서 완전한 우회를 보장하는 경로 탐색은 아니다.

일반 적 명칭은 Slime(슬라임), Turtle Monster(터틀 몬스터), Rock Golem(록 골렘), Lich(리치), Grunt(그런트)다. 코드·프리팹 이름은 `Slime`, `TurtleMonster`, `RockGolem`, `Lich`, `Grunt`이며 기존 데이터 ID와 풀 Enum 번호는 유지한다. 이벤트 무리는 `SwarmSlime`으로 구분한다. 원본 모델 에셋 이름은 변경하지 않으며 애니메이션 적용은 이후 작업이다.

### 시간대별 생성

- EnemySpawner가 TimeSystem.ElapsedSeconds로 현재 시간대를 고른다. 적 종류별 가중치로 추첨하며 화면 밖에 생성한다.
- 스폰 간격마다 일반 적 수가 최소 수보다 부족하면 부족분을 채운다. 최소 수는 최대 수 이하로 제한한다. 최대 수까지 계속 보충하는 방식은 아니다.
- 시간대 전환 후 기존 적은 유지한다. 새 종류는 부족분 보충 때 등장하며 최대 수가 낮아져도 기존 적을 강제 제거하지 않는다.

### 이벤트 슬라임 — 위치 기반 이동이 현재 기준

- 등장 시각은 125 / 130 / 135 / 425 / 430 / 435초, 즉 2:05·2:10·2:15·7:05·7:10·7:15다. EventEnemies.json의 spawnTimes에 정의되어 있다.
- 일반 슬라임와 별도인 SwarmSlime 풀을 사용하고 일반 적 최소/최대 수에서는 제외한다. 외형과 적 데이터 ID 1은 일반 슬라임와 공유한다. 이벤트 최대 활성 수가 부족하면 남은 자리만 생성하고 나중에 보충하지 않는다.
- 화면 밖 랜덤 위치에서 간격을 둔 마름모형 대형으로 등장한다. 생성 순간 플레이어 위치로 방향을 확정하고 이후 추적·재조준하지 않는다.
- **이벤트는 Rigidbody 속도 추적이 아니다.** Collider 전환 이전의 누적 거리 기반 이동을 복구했다. 생성 위치 + 최초 방향 × 진행 거리를 기준으로 오프셋을 복귀시키고 최대 이탈 범위를 제한한다. 보정 후에도 다시 경로 이탈을 제한한다.
- SwarmSlime.prefab에 이벤트 전용 컴포넌트와 물리 설정을 저장한다. 일반 적의 Dynamic / Collider 활성 / Enemy 레이어와 이벤트의 Kinematic / Collider 비활성 / EnemySwarm 레이어를 코드로 전환하지 않는다. 질량·레이어·충돌 모드 저장/복원은 없으며 일반 적의 시계 정지 해제용 constraints 복구만 유지한다.
- 이벤트의 Rigidbody는 Kinematic, Collider는 비활성이다. 장애물과 플레이어를 통과한다. 무기 명중·피해·사망·플레이어 접촉 피해는 기존 거리 판정으로 유지한다.
- EnemyCrowd는 이벤트가 있을 때만 이벤트-일반 적 쌍을 격자로 찾아 기존 가중치·접촉 평균·속도 제한이 있는 보정을 적용한다. 일반 적의 보정은 Rigidbody.position에 연결하고 장애물까지의 이동 거리로 제한한다. 일반 적끼리는 계속 Physics가 처리한다.
- 일반 적을 미는 방향에서는 이벤트 진행 방향에 반하는 성분을 제거한다. 슬라임 통과 후 반대 보정으로 밀림이 취소되는 현상을 방지하며 측면 밀림은 유지한다.
- Swarm Push Strength는 Rigidbody 질량이 아닌 겹침 보정 가중치다. 일반 가중치=1, 이벤트 가중치=1/강도다. 현재 보정 반복은 2회다.
- 현재 EventEnemies.json ID 1 값: **이벤트당 50마리, 최대 활성 120, 속도 16, 강도 5, 간격 1.3, 최대 경로 이탈 0.25, 복귀 속도 4**. 해당 값의 중복 Inspector 설정은 제거했다.
- 일반 적 프리팹의 Swarm Push Speed는 현재 3이다. 일반 적에게 주는 보정은 물리 스텝 전체에서 최대 `값 × deltaTime`이며 반복 횟수만큼 증폭하지 않는다. 실제 이동·일반 적 간 Physics 반응을 합친 총 변위의 상한은 아니다.
- 무리 전체 대기·가장 느린 슬라임 기준 이동·공유 슬롯 추적·가속 기반 복귀는 사용하지 않는다. 일부가 밀려도 다른 슬라임는 계속 이동한다.

### 이벤트 JSON 설정과 추가 방법

- `Assets/Resources/JSON/EventEnemies.json`을 기존 DataManager / DataTable<EventEnemyData>로 로딩한다. Id는 이벤트 테이블 안에서 고유하며 EnemyData의 Id와 별개다. 체력·피해·드롭은 이벤트 프리팹의 Data Id가 참조하는 Enemies.json을 계속 사용한다.
- Spawner는 이벤트 레코드를 자동으로 등록해 각 spawnTimes의 시각에 실행한다. count는 1회 생성 수, maxActive는 해당 이벤트 ID의 최대 활성 수다. 일반 적 및 다른 이벤트 ID의 활성 수는 이 상한에 포함하지 않는다. 상한 때문에 생성하지 못한 수는 뒤늦게 보충하지 않는다. maxActive=0으로 해당 이벤트 생성을 끌 수 있다.

| 필드 | 역할 |
| --- | --- |
| Id / poolType | 이벤트 ID / PoolTypeEnums 이름(현재 SwarmSlime) |
| spawnTimes | 게임 내 생성 시각(초), 중복 없는 오름차순 |
| count / maxActive | 1회 생성 수 / 이벤트 종류별 최대 활성 수 |
| moveSpeed / spacing | 이동 속도 / 대형 간격 |
| pushStrength | 기존 겹침 보정 가중치, 질량이 아님 |
| maxOffset / recoverySpeed | 최대 경로 이탈 / 오프셋 복귀 속도 |
| directionMode | ToPlayer 또는 Fixed |
| directionX / directionZ | Fixed일 때 필수인 월드 XZ 방향 성분. 정규화하여 사용 |

- 기본 슬라임는 ToPlayer다. 생성 순간 플레이어 위치를 기준으로 방향을 한 번 정하며 이후 추적하지 않는다.
- Fixed는 플레이어 위치와 관계없는 월드 방향이다. 예를 들어 directionMode=Fixed, directionX=1, directionZ=0은 +X로 이동한다. 화면 안으로 진입할 수 있는 변에서 생성하고 이후 방향을 바꾸지 않는다.
- 새 이벤트는 ObjectPool enum / PoolDataInitializer에 이벤트 프리팹을 등록한 뒤 새 ID의 JSON 레코드를 추가한다. 프리팹에는 EnemySwarmMovement와 EnemyHealth가 필요하다. 현 구조는 기존 고정 경로·마름모 대형을 공유하며 새로운 이동 알고리즘까지 JSON만으로 만드는 범위는 아니다.
- 모델·물리 설정·명중 반경·이벤트 보정 속도는 프리팹에, 일반 적 시간대·화면 검사 간격·생성 높이/여유는 Spawner Inspector에 유지한다. JSON 변경은 새 Play부터 적용한다.

### 화면 밖 반환과 사망

- EnemySpawner가 현재 Game 카메라 화면을 0.2초 간격으로 일괄 검사한다. 활성 Renderer의 Bounds가 하나라도 보이면 화면 안으로 판단한다.
- 일반 적은 화면 밖 시간 누적 후 데이터의 지연 시간에 반환한다. 제한 전 다시 들어오면 타이머를 초기화한다.
- 이벤트는 한 번 화면 안에 들어온 뒤 몸체가 완전히 벗어날 때 반환한다. 생성 직후 화면 밖이라는 이유로 반환하지 않는다. 고정 이동 거리·수명 기준은 없다.
- 0.2초 사이의 짧은 화면 진입을 놓칠 수 있는 샘플링 한계는 남아 있다.
- EnemyHealth는 HP 0에서 한 번만 사망을 확정하고 보석을 드롭한다. 이동·충돌·접촉 피해와 명중 검색을 중단한 뒤 Die 애니메이션이 끝나면 풀로 반환한다. 치명타는 GetHit 없이 Die로 전환하고 사망 후 Hit는 무시한다. 재사용 시 체력·Idle·Trigger·Collider·이동·타이머·이벤트 상태를 초기화한다.
- EnemyMovement가 실제 XZ 이동량으로 IsMoving을 갱신하고, EnemyHealth는 피격·사망과 Animator 초기화를 담당한다. 일반 적의 실제 이동은 EnemyDefaultMovement, 이벤트 이동과 밀어내기 보정은 EnemyCrowd / EnemySwarmMovement가 담당한다.
- 현재 바닥 윗면은 Y=0, 적 생성 루트는 Y=1이다. 모델의 Local Y를 -1로 두고 Collider 중심도 같은 만큼 내려 외형과 충돌체를 맞춘다. 장애물 감지는 실제 Collider 중심에서 수행하며 전투·이벤트 경로의 루트 높이는 유지한다.

## 6. 자동 공격과 무기

### 공통 구조

- Weapon이 보유·최대 8레벨·공통 배율·쿨타임을 관리한다. 무기별 UpgradeWeapon 오버라이드가 JSON 강화 변화량을 실제 값에 더한다.
- WeaponManager에 등록한 무기 프리팹이 선택 후보다. 획득할 때 플레이어 아래 인스턴스를 생성한다. 시작 무기는 선택한 캐릭터의 weaponId다.
- 플레이어 입력 방향·공격 원점·카메라는 WeaponManager가 전달한다. 무기가 PlayerMovement를 직접 참조하지 않는다.
- 지팡이·단검·채찍은 연사 시작부터 다음 연사 시작까지를 쿨타임 기준으로 삼는다. 연사 중 쿨타임이 끝나도 현재 연사를 마친 뒤 다음 공격을 시작한다.
- 피해량은 무기가 계산해 발사/공격 시 전달한다. 명중은 IDamageable로 피해를 전달하며 넉백과 관통을 처리한다.
- 지팡이·단검은 공통 Projectile을 쓴다. 발사 후 직진하고 적을 추적하지 않는다. 관통 횟수는 총 맞힐 수 있는 대상 수이며 초기 1은 첫 명중에 제거됨을 뜻한다.
- EnemyCrowd의 격자로 이동 구간 주변 후보만 검색한 뒤 구간 거리 판정으로 빠른 투사체의 누락을 줄인다. 적·횃불 중 첫 접촉 순서로 처리한다. 명중용 Body Radius는 물리 충돌 반경과 별도다.
- 같은 투사체/베기의 중복 명중은 제외한다. 성경은 무기 전체에서 적별 재피격 시간을 공유하며 풀 재사용 버전도 구분한다.

## 7. 경험치와 레벨업 선택

- 적 드롭 확률은 현재 전 종류 60%, 보석 기본 XP는 1이다. 보석은 사망 위치의 바닥에 생성하고 풀을 사용한다.
- ExperienceGem은 자식 모델의 최하단 높이를 풀 생성 시 계산한다. 루트 MeshFilter가 없어도 드롭되며 자식 위치·회전·스케일을 반영한다.
- PlayerExperience의 기본 흡인 범위는 현재 Players.json에서 1, 속도는 10이다. 자식 SphereCollider 센서 접촉 시 보석 추적을 시작하고 몸체 접촉 시 XP를 지급한다.
- 보석은 한 번 끌리기 시작하면 플레이어를 계속 따라온다. 획득은 OnTriggerEnter로 처리하고 중복 지급을 막은 뒤 풀로 반환한다.
- 레벨은 1부터, 필요 XP는 `initialExp + (현재 레벨 - 1) × expGrowth`다. 현재 5, 15, 25, 35…이며 초과분 이월·연속 레벨업을 처리한다.
- GameManager가 오른 레벨 수만큼 선택 기회를 보관한다. 기존 자동 무기 강화는 없다.
- 무기·장신구 후보를 합쳐 중복 없이 추첨한다. GameScene의 카드 수는 2이며 카드 배열을 늘려 표시 수를 확장할 수 있다.
- 카드에는 이름·신규 또는 적용될 다음 레벨·획득/강화 설명·아이콘 자리를 표시한다. TextMeshProUGUI를 사용한다.
- 선택하면 획득/강화 후 재개한다. 대기 중인 선택이 남으면 시간을 재개하지 않고 다음 선택을 표시한다.
- 무기 보유 한도는 시작 무기 포함 3개, 레벨업으로 얻는 장신구 한도도 3개다. 한도가 차면 미보유 후보만 제외하며 보유 항목 강화는 가능하다.
- 무기 8레벨·장신구 5레벨은 선택지에서 제외한다. 후보 하나면 카드 하나를 중앙에 표시하고, 후보가 없으면 선택 기회를 정리하고 계속 진행한다.

## 8. 장신구와 맵 획득

- Accessory가 획득·최대 5레벨·강화를 관리한다. AccessoryManager는 등록한 프리팹을 획득 시 생성하며 각 하위 클래스는 효과를 적용한다.
- DisplayName·BonusPerLevel·선택 설명은 Accessories.json에서 읽는다. 아이콘은 프리팹 Sprite 참조다.
- `L`은 보유 레벨, 미보유는 0이다. 강화는 획득 즉시 적용하고 해당 플레이 종료까지 유지한다.

| ID | 장신구 / 클래스 | 효과 |
| --- | --- | --- |
| 1 | 날개 / Wings | 기본 이동 속도 × (1 + 0.1L), 최대 +50% |
| 2 | 검은 심장 / HollowHeart | 매 단계 현재 최대 HP × 1.2 후 반올림. 현재 HP는 회복하지 않음 |
| 3 | 시금치 / Spinach | 무기 자체 강화 후 피해량 × (1 + 0.1L), 최대 +50% |
| 4 | 빈 책 / EmptyTome | 무기 자체 강화 후 쿨타임 × (1 − 0.08L), 최대 −40% |
| 5 | 매혹구(매혹의 오브) / Attractorb | 기본 보석 흡인 범위 × (1 + 0.2L), 최대 +100% |

- 검은 심장은 HP 100 기준 120 → 144 → 173 → 208 → 250이다. 나머지 장신구는 기본값 기준 보너스를 합산한다.
- 빈 책은 쿨타임에만 적용한다. 연사 간격·지속시간·성경 재피격 간격은 바꾸지 않는다.
- 보너스는 이후 획득한 무기에도 전달된다.
- GameScene에 검은 심장·시금치·빈 책의 MapAccessory 3개를 고정 배치한다. 현재는 씬 Transform으로 위치와 3D 외형을 편집한다. Sprite 배치/시작 위치 상대 배치 전용 로직은 없다.
- MapAccessory는 청크와 독립적이다. 새 장신구는 레벨업의 3개 한도를 무시하고 획득하여 5종까지 보유할 수 있다. 이미 보유하면 +1레벨, 최대 레벨이면 획득하지 않고 맵에 유지한다.
- 성공적으로 획득한 맵 장신구는 제거되며 해당 플레이에서 다시 생성되지 않는다. 새 게임은 씬에서 다시 시작한다.

## 9. 맵·장애물·보석 유지

- MapGenerator는 단일 ForestChunk 프리팹을 회전·랜덤 배치 없이 XZ 격자로 반복한다. 현재 청크 크기는 64×64다. Ground 중심은 (32, -0.15, 32)이며 로컬 XZ 0~64를 덮는다. 환경 배치는 기존 바닥과의 상대 위치를 유지하도록 X/Z로 각각 16 이동했고, 가로·세로 길은 중심 32에서 청크 경계까지 연결한다.
- Keep Radius=1로 대각선을 포함해 기본 3×3을 유지한다. 현재 카메라 지면 투영과 View Padding=8에 따라 더 넓힐 수 있으며 Inspector에서 조절한다.
- 경계를 넘으면 필요한 청크만 재배치한다. 멀어진 청크는 반환한 뒤 재사용한다. 같은 좌표로 돌아오면 고정 환경 배치도 같다.
- 나무·돌은 Obstacle Collider로 플레이어와 일반 적을 막는다. 풀은 통과 가능하다. 이벤트 슬라임는 장애물을 통과한다.
- 적·보석·드롭 아이템·맵 장신구는 청크 자식으로 관리하지 않는다. 청크 반환으로 함께 제거되지 않는다.
- 보석과 드롭 아이템은 중력으로 바닥을 요구하지 않으므로 멀리 이동했다 돌아와도 남는다. 현재는 활성 오브젝트를 유지하며 원거리 보석 직렬화/비활성 복원 시스템은 없다.

## 10. 횃불과 드롭 아이템

- TorchSpawner가 청크 배치 이후 플레이어 화면 밖·바닥·장애물·횃불 간격을 확인해 생성한다. 청크의 고정 배치물이 아니며 풀을 사용한다.
- TorchSpawns.json의 ID 1: 검사/생성 간격 3초, 생성 확률 1(100%), 최대 12개, 화면 밖 여유 거리 2, 최소 간격 2, 배치 시도 8회, 반환 거리 70. TorchSpawner의 Data Id로 연결하며 플레이어·카메라 참조와 ground/obstacle LayerMask는 Inspector에 유지한다.
- Torch의 현재 HP는 1이다. 무기 구간 판정으로 공격받고 파괴 시 한 번만 드롭을 결정한 뒤 반환한다.
- Torch 프리팹의 Inspector에서 드롭 없음 50% / 치킨 30% / 흡입기 12.5% / 시계 7.5%를 각각 편집한다. 합계는 비례 정규화해 100%를 유지하며 모두 0이면 드롭 없음 100%로 처리한다.

| 아이템 | 현재 효과 | 수치 위치 |
| --- | --- | --- |
| 치킨 | HP 30 회복, 최대 HP 초과 불가 | Chicken 프리팹의 PickupItem |
| 흡입기 | 화면 밖을 포함한 현재 활성 보석 전체를 플레이어로 흡인 | VacuumPickup 프리팹, 흡인 속도 10 |
| 시계 | 일반 적과 이벤트 슬라임의 이동·접촉 피해를 5초 정지 | ClockPickup 프리팹, Freeze Duration |

- 아이템은 플레이어 몸체 접촉 시 한 번 효과를 적용하고 반환한다. 보석 흡인 센서 접촉은 획득으로 처리하지 않는다.
- 시계 중에도 적의 피격·처치가 가능하며 새로 생성된 적/이벤트도 남은 시간 동안 정지한다. 재획득은 현재 게임 시간부터 지속 시간을 갱신한다.
- 시계는 생존 타이머나 이벤트 일정을 멈추지 않는다. 게임 자체의 정지·레벨업 선택 중에는 시계 남은 시간도 줄지 않는다.
- 드롭 아이템은 획득 전까지 유지하며 청크 반환과 독립적이다.
- Torch 드롭은 루트와 자식 MeshFilter의 Bounds 모서리를 월드 좌표로 변환해 모델 최하단을 바닥에 맞춘다. 자식 모델·피벗·크기·회전을 반영한다.

## 11. HUD와 사운드

### UI

- PlayerHPBar는 플레이어 아래의 월드 기준점을 화면 좌표로 변환해 HUD Slider에 현재 HP 비율을 표시한다.
- 화면 최상단 경험치 바는 현재 XP / 다음 레벨 필요 XP, 오른쪽 레벨은 LV1 형식이다.
- TimerUI는 경험치 바 아래 중앙에서 `00 : 00` 형식으로 생존 시간을 표시한다. TimeSystem은 표시 초가 바뀔 때 알린다.
- OwnedItemsHUD는 왼쪽 위에 무기 3칸, 그 아래 기본 장신구 3칸을 표시한다. 보유 여부만 표시하고 레벨은 표시하지 않는다.
- 맵 획득으로 장신구 한도를 넘으면 HUD 슬롯을 추가한다. 기본 빈칸은 유지하고 미보유 추가 칸은 숨긴다.
- 장신구는 실제 아이콘 참조가 있다. 현재 무기 4종의 icon은 None이다. HUD는 프로젝트 내부 임시 Sprite를 대체 표시하고, 선택 카드는 아이콘을 숨긴다.

### 사운드

- SoundManager는 기존 Singleton을 사용하고 씬 전환에도 하나만 유지한다. StartScene·GameScene 모두 공통 프리팹을 배치해 직접 실행도 지원한다.
- BGM 키는 StartScene / GameScene이다. SFX는 무기 공격 4종, 적 피격/사망, 플레이어 피격, 경험치 획득, 레벨업, 결과, UI 클릭, 횃불 파괴에 연결되어 있다.
- 음원이 없으면 재생을 생략한다. 현재 프리팹의 BGM/SFX Audio Clip 15개는 모두 None이며 실제 음원 적용은 남아 있다.
- 프리팹의 BGM/SFX List에서 기존 이름을 유지해 음원을 연결한다. 기본 BGM 볼륨 0.3, SFX 1, 채널 16이며 같은 소리 최소 재생 간격도 조절한다.
- 정지/선택 중에는 전투 SFX를 중단하고 BGM은 유지한다. 결과 시 BGM도 정지한다. UI·결과 소리는 timeScale 0에서도 허용한다.
- 볼륨 변경 API는 있지만 사용자 설정 UI·설정 저장은 없다. 현재 필수 범위로 확정하지 않았다.

### JSON

| 파일 (Assets/Resources/JSON) | 관리 항목 |

| Weapons.json | 이름·획득 설명·공격 유형·기본 수치·2~8레벨 변화량과 설명 |

- DataManager → DataTable<T> → 각 Data 클래스로 로딩/조회한다. Resources/JSON을 동기 로딩하며 플레이 진입 시 캐시를 초기화한다.
- 필수 JSON 누락, ID 중복과 유효성, 무기 공격 유형별 필수 설정, 강화 개수·순서·설명 등을 검증한다. 현재 수치 유효성 검사도 각 Data 클래스에 존재한다.
- ID는 테이블 안에서 고유하다. 적 ID 1, 무기 ID 1, 장신구 ID 1은 함께 사용 가능하며 PoolTypeEnums와 별개다.
- 무기 공통 필드는 필수이고, 전용 필드는 공격 유형에 따라 요구된다. GetUpgrade는 2~8레벨의 해당 레코드를 반환한다.
- 강화 설명은 JSON description을 읽고 `{damage}`·`{projectileCount}` 등의 자리표시자를 치환한다. 강화 효과 종류를 한국어로 하드코딩해 조합하지 않는다.
- 프리팹 Data Id와 JSON을 연결한다. 이벤트는 EventDataId로 자신의 이벤트 레코드를 구분하며 풀 재사용 시 초기화한다. 아이콘·모델·카메라·타깃·UI·레이어·충돌 반경·일반 적 스폰 시간대·횃불 드롭 확률·풀 수량은 씬/프리팹 설정이다.
- JSON 변경은 임포트 후 새 Play에 반영한다. 배포 외부 파일 편집·실행 중 자동 재읽기는 구현하지 않았다.

### 풀과 역할

- PoolDataInitializer가 풀 데이터를 한곳에서 등록한다. ObjectPool은 Queue로 재사용하며 반환 실패 시 정리하는 공통 처리를 담당한다.
- 풀 대상은 일반 적 5종·이벤트 슬라임·경험치 보석·청크·횃불·치킨·흡입기·시계다. 일반 슬라임는 Slime(0), 이벤트 슬라임는 SwarmSlime(11) 풀로 분리한다. 기존 풀 enum 번호는 유지한다. GameScene의 이벤트 풀 사전 준비 수는 50이다.
- 지팡이·단검 투사체와 채찍 베기는 Instantiate/Destroy다. 성경 큐브는 무기 내부에서 생성 후 재활성화한다. 무기 투사체 풀링은 아직 없다.

## 13. 성능 측정과 비교 테스트

- 임시 성능 측정용 ProfilerMarker와 Auto 스코프는 게임 코드·비교 테스트·LegacyGrid 보관본에서 제거했다. 게임 동작과 비교 테스트의 알고리즘은 유지한다.
- Unity Profiler의 CPU Usage에서 기본 MonoBehaviour 호출(FixedUpdate / LateUpdate 등)과 Physics 구간을 확인한다. 제거된 사용자 정의 마커 이름으로는 검색되지 않는다.
- Physics는 Timeline의 FixedUpdate.PhysicsFixedUpdate / Physics.Simulate 등 실제 표시 구간과 워커 스레드를 함께 확인한다. 부모 시간과 자식 시간을 중복 합산하지 않는다.
- 상세 함수별 계측이 다시 필요하면 해당 구간에 한정해 추가한다. Deep Profile은 측정 부하가 달라지므로 기본 성능 비교와 구분한다.
- GameScene 또는 Development Build에서 초기화 이후 15~30초 기록한다. 적 수·밀도·무기/레벨·장애물·플레이어 이동 조건을 맞추고 정지/레벨업 선택은 전투 구간과 분리한다.
- EnemySpawnTest의 1/2/3은 각각 100/300/500마리를 ‘추가’한다. 스폰·처치·반환이 있으므로 당시 실제 활성 수를 확인한다.
- 컴포넌트 분리 시 전체 C# 컴파일, 프리팹 물리 설정 보존/참조 검사와 분리 전후 400프레임의 위치·속도 기록 일치를 모의 물리 환경에서 확인했다. 실제 Unity Physics 플레이 검증과는 구분한다.
- EnemyCrowdComparison 씬은 500/1000/1500마리의 별도 비교용이다. Grid 모드는 Test/EnemyComparison/LegacyGrid에 보관한 구현을 사용하며 현재 게임의 일반 적 이동이 아니다. 비교용 Collider도 게임 코드와 분리돼 있다.
- 비교 테스트가 프레임·GC·기본 Physics 통계를 기록하는 ProfilerRecorder는 유지한다. 사용자 정의 마커 제거와 CSV 통계 기능 제거는 별개다.
- 실제 게임에는 일반 적 전체의 SimulateCrowd / GetSeparation / CorrectOverlap 반복이 없다. 과거 Grid 측정값을 현재 게임 성능으로 취급하지 않는다.

## 14. 남은 작업과 완료 확인

## 15. 코드 작성 원칙

- 신입 개발자가 이해할 수 있는 일반 C#과 명확한 책임 분리를 우선한다. LINQ·과도한 추상화·새 매니저를 필요 없이 추가하지 않는다.
- 기존 구조와 정상 동작을 유지하고 요청한 기능에 필요한 변경만 한다. 새 클래스가 필요하면 역할과 이유를 먼저 설명한다.
- 가상의 확장성과 성능을 이유로 시스템을 미리 만들지 않는다. 실측과 실제 요구에 따라 개선한다.
- 구현 후 핵심 흐름·변경 이유·확인 방법을 간단히 설명한다. 컴파일/모의 검사와 Unity 실제 플레이 검증을 구분한다.
- 특히 정상 작동 중인 일반 적 이동과 이벤트 슬라임 대형은 관련 요청 없이 변경하지 않는다.
